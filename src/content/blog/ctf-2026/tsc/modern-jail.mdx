## <Color c="red-0">解題過程</Color>

1. 從 `server.lua` 中我們能發現 `load(code, "user", "t", env)` ，伺服器把 POST body 當 Lua chunk
   執行，這是一題 Lua jailbreak 。其中「獨立環境 table」是題目作者透過 load function 的第四個參數 env 明確指定的

![image](@assets/blog-images/2026/tsc/modern-jail/verify-main-logic.png)
![image](@assets/blog-images/2026/tsc/modern-jail/how-execute-work.png)

&emsp;

2. Code audit ，仔細查看會發現，在真正 load 之前，有經過 `build_safe_env()`
   ，這個函式前面定義了很多變數，目的是為了做到清除像是 string 對於 table 內敏感元素的關聯，所以定義了
   `safe_string` 這個新的 table ，用來用來取代完整的原生 string 模組。因為這是在 `load(code, "user", "t", env)`
   環境，透過複製了特定安全函式的 reference ，清空原本環境裡面的<Color c="blue-3">參考綁定</Color>，防止攻擊者透過
   Table 屬性遍歷去存取到不在白名單內的危險欄位(函式、元素)

<AlertBlockquote
  type="info"
  title="關於 Lua 的表索引路徑 (table indexing path)"
>
  Lua 沒有類別的概念，注意這並不是說 Lua
  沒有物件的概念，畢竟類別不是物件的唯一來源。而 Lua 中用來實作物件(鍊)的就是
  table ，可以使用多個 table 配合 Lua 語法糖 `:` 把前一個動作的 output
  當成下一個動作的 self 傳入
</AlertBlockquote>

{/* prettier-ignore */}
<AlertBlockquote
  type="info"
  title="關於 Lua 的變數宣告"
>
  Lua 5.1 中，未宣告 local
  的變數會被編譯成對當前函式環境表的存取；預設環境通常是 `_G` ，但可被替換\
  在官方文件 [Section 2.4.3 - Assignment](https://www.lua.org/manual/5.1/manual.html#2.4.3) 
  就有提到：\
  An assignment to a global variable `x = val` is equivalent to the assignment `_env.x = val`\
  而在 [Section 2.3 - Variables](http://lua.org/manual/5.1/manual.html#2.3) 也提到了
  <Color c="red-0">任何變數預設都是全域變數</Color>：\
  Any variable is assumed to be global unless explicitly declared as a local
</AlertBlockquote>

```lua
local function execute(code)
  module = nil
  _G = nil
  os = nil
  io = nil
  package = nil
  dofile = nil
  loadfile = nil
  ...

  local env = build_safe_env()
	local fn, err = load(code, "user", "t", env)

  ...
end
```

&emsp;

3. 那麼問題出在哪裡呢？真正的問題點在於 `setmetatable` 這個 table 裡面的 `__index` ，這個 metamethod
   (元方法)的觸發時機是<Color c="red-0">當讀取了一個不存在的屬性</Color> ，就會執行後續的函式，在這裡就是
   `function(_, k) return rawget(_G, k) end`

{/* prettier-ignore */}
<AlertBlockquote type="info" title="關於 setmetatable">
  `setmetatable(table, metatable)` 固定接收兩個參數(本來是用來實作原生 table 沒有的功能)：\
  (1) table 用來存放具體的屬性或資料\
  [關於 setmetatable](https://www.lua.org/manual/5.1/manual.html#pdf-setmetatable)\
  (2) metatable 用來存放「規則」，規則裡面的方法會用 `__` 開頭命名(稱為元方法)\
  [關於 metatable 和 metamethod](https://www.lua.org/manual/5.1/manual.html#2.8)\
  (3) 因為 `__index` 這個元方法必須吃兩個參數 `__index(table, key)` ，所以才要寫成 `function(_, k)`
</AlertBlockquote>

```lua
local function build_safe_env()
  local safe_string = {
    ...
  }

  local safe = {
    ...
  }

  -- Intentional flaw: expose fallback to real globals
  setmetatable(safe, {
    __index = function(_, k)
      return rawget(_G, k)
    end,
  })
  return safe
end
```

&emsp;

4. 關鍵是 OpenResty 為了防止併發請求互相污染，會為每個 HTTP Request 建立一個「專屬的子環境表」，並且透過 `__index`
   繼承底層真正的全域表。題目的 execute 函式其實是跑在這個「子環境」中。因此，當程式執行 `_G = nil`
   時，他只是在當前 Request 的空表中設定了一個無效的 nil ，底層的全域表 `_G` 依然完好無缺。當執行 `rawget(_G, k)`
   並觸發 `__index` 時， Lua 引擎會解析 table 底下的 index `k` ，發現當前子環境找不到 (因為被設為 nil了) ，就會利用環境表的
   fallback 機制，拿到底層的環境變數 `_G`

```lua
function(_, k)
  return rawget(_G, k)
end,

-- rawget(table, index)
```

</AlertBlockquote>
