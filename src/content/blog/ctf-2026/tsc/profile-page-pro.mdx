## <Color c="red-0">解題過程</Color>

1. 看一下給的 source code ，在 `index.js` 中可以看到 `app.get('/', ...)` 的 router 中，有一個和 flag 有關的函式

```js
if (req.query.setdown === "1") {
  if (
    FLAG[+[] + profile.name.length++ + ![]] ===
      profile.bio[+[] + profile.name.length++ + ![]] &&
    !Object.hasOwn(profile, "toString")
  ) {
    FLAG = !++req./*^_^*/ query./*^_^*/ setdomn /*^_^*/;
  }
}
```

- 如果有 `?setdown=1` 就能夠進內層 if 判斷式
- 看起來很複雜，但是拆解一下會發現由於 `+[]` 轉型為 0 且 `![]` 轉型為 false (在數學運算中等同於 0)
- 所以 `+[] + profile.name.length++ + ![]` 實際上等於 `profile.name.length`
- 那麼整個內層 if 判斷式就相當於比較 `FLAG[profile.name.length] ===  profile.bio[profile.name.length] && !Object.hasOwn(profile, "toString")`

&emsp;

2. 而 `!Object.hasOwn(profile, 'toString')` 這一點又限制了 profile 物件不能定義 toString 的屬性，這代表不能簡單地對 profile 用 toString() 做
   prototype pollution 嘗試 leak 出 flag ，但是 profile 本身是正常的 JSON 格式，那 `!Object.hasOwn(profile, 'toString')`
   就會恆真，代表前面的<br />
   `FLAG[profile.name.length] ===  profile.bio[profile.name.length] && !Object.hasOwn(profile, "toString")`<br />
   等價於 `FLAG[profile.name.length] === profile.bio[profile.name.length]`

<br />
- profile 是 `Object.freeze({ name, bio, photo })`
- 而且如果 profile.name 是一個字串，在 js 中對唯獨屬性做 ++ 是<Color c="red-0">不會</Color>
  改變字串本身的長度。後續如果我要猜 flag 的第 3 位，我就在 bio 的第 3 位進行對應的處理


&emsp;

3. 之所以前面這串 if 需要拆解，就是為了進入 if 迴圈，執行 `FLAG = !++req./*^_^*/query./*^_^*/setdomn/*^_^*/;` ，
   `/*...*/` 就是 js 的註解，所以前面這一整段相當於 `FLAG = !++req.query.setdomn;` 。關鍵是 js 在運算 `++obj` 時
   ，因為有 `++` 的存在 (hint number)， Node.js 的 v8 引擎會：<br />

   (1) ToPrimitive (把物件轉換回原始型別)<br />

   (2) 普通物件先試 `valueOf()`，若不是 primitive (原始型別) 再嘗試 toString()<br />

   (3) `toString()` 函式的回傳是字串就轉換成 number<br />

5. 那麼當我直接修改 `toString()` 這個函式， if 判斷式出錯沒正常執行後續的 JS ，就能創造出 side-channel attack
   的效果 — 猜對 flag 特定位元時， HTTP 狀態碼會出錯 (因為 `toString()` 被我修改了)；猜錯的話就進不去 if
   ( step 2 強調 if 判斷等價 `FLAG[profile.name.length] === profile.bio[profile.name.length]`)

<br />

- 當然，這與 JS 的屬性有關聯， JS 物件原型鍊的 `toString()` 來自 `Object.prototype.toString` ，但是
  我如果把這個物件加上 `toString()=x` 屬性值， Node.js v8 引擎就會先採用我加上的這個屬性值 `x`
- 所以我可以對 `/` 做 GET 請求的同時， query string 使用 `?setdown=1&setdomn[toString]=x` ，這樣就
  能完美符合 side-channel attack 的條件

```python
CTFD_URL = "https://ctfd.tscctf.com"
CHALLENGE_ID = 2

ctfd_session = requests.Session()
ctfd_session.headers.update({
    "Accept": "application/json",
    "User-Agent": "Mozilla/5.0 ...",
    "Origin": "https://ctfd.tscctf.com",
    "Referer": "https://ctfd.tscctf.com/challenges",

    "Cookie": "session=...",
    "CSRF-Token": "..."
})


def reset_instance():
    # --- 先銷毀舊的環境 ---
    print("\n[*] 正在銷毀舊 Instance...")
    destroy_url = f"{CTFD_URL}/plugins/instance-challenges/destroy/{CHALLENGE_ID}"
    try:
        # 加上 json={} 讓 Content-Length 變成 2，符合真實瀏覽器行為
        res_del = ctfd_session.post(destroy_url, json={})
        print(f"    -> Destroy 回應: HTTP {res_del.status_code}")
        time.sleep(1) # 給伺服器 1 秒鐘的時間釋放 Docker 資源
    except Exception as e:
        print(f"    [-] 銷毀時發生異常: {e}")

    # --- 建立新的環境 ---
    print("[*] 正在請求建立新 Instance...")
    create_url = f"{CTFD_URL}/plugins/instance-challenges/create/{CHALLENGE_ID}"
    try:
        res_create = ctfd_session.post(create_url, json={})
        print(f"    -> Create 回應: HTTP {res_create.status_code}")
        if res_create.status_code not in [200, 302]:
            print(f"    -> 伺服器回傳內容: {res_create.text[:200]}")
    except Exception as e:
         print(f"    [-] 建立時發生異常: {e}")

    # --- 查詢狀態 ---
    print("[*] 等待環境啟動並擷取網址...")
    status_url = f"{CTFD_URL}/plugins/instance-challenges/status/{CHALLENGE_ID}"

    max_retries = 15
    for _ in range(max_retries):
        time.sleep(2)
        try:
            res_status = ctfd_session.get(status_url)
            if res_status.status_code == 200:
                data = res_status.json()
                if "accesspoint" in data and data["accesspoint"]:
                    match = re.search(r'href="(.*?)"', data["accesspoint"])
                    if match:
                        new_url = match.group(1).strip()
                        print(f"[+] 伺服器就緒！分配到新網址: {new_url}")
                        return new_url
        except Exception as e:
            pass

    print("[-] 等待環境啟動超時！請檢查上方 Create/Destroy 的 HTTP 狀態碼。")
    sys.exit(1)
```
